# Каталог SPF-рекомендаций

Единым источником данных для локальной и production-БД является
`catalog/spf.catalog.json`. Excel используется как удобный редактор, но сам
файл `data/spf.xlsx` остаётся локальным и не разворачивается на сервере.

## Обычный процесс обновления

1. Получить от врача новые товары и правила рекомендаций.
2. Обновить лист `Вопросы и логика` в `data/spf.xlsx`.
3. Запустить локальные контейнеры.
4. Выполнить одну команду:

   ```bash
   docker compose exec app npm run catalog:update
   ```

5. Команда последовательно:
   - преобразует Excel в `catalog/spf.catalog.json`;
   - проверяет структуру, ссылки на товары, дубликаты правил и покрытие;
   - сохраняет версионируемый JSON;
   - транзакционно синхронизирует локальную БД.
6. Проверить изменения JSON через `git diff`.
7. Пройти затронутые сценарии в тестовом боте и Mini App.
8. Закоммитить JSON вместе с кодом и отправить изменения через обычный
   dev-main → main процесс.
9. После production deploy сервис `migrate` автоматически запускает
   `npm run catalog:sync`.

## Команды

Только создать JSON из Excel:

```bash
docker compose exec app npm run catalog:generate
```

Проверить существующий JSON:

```bash
docker compose exec app npm run catalog:validate
```

Синхронизировать БД из JSON без чтения Excel:

```bash
docker compose exec app npm run catalog:sync
```

Полный локальный процесс Excel → JSON → БД:

```bash
docker compose exec app npm run catalog:update
```

## Правила заполнения Excel

- Одна строка задаёт одно правило:
  `Тип кожи + Особенность + Образ жизни`.
- Значение `Любой` создаёт fallback сразу для обычного и активного образа
  жизни, если для них нет более точных правил.
- Название товара является его идентификатором в каталоге и должно
  записываться одинаково во всех строках.
- Если один товар встречается несколько раз с разными свойствами, конвертер
  покажет предупреждение и сохранит первые непустые значения. Такие
  предупреждения нужно устранить в Excel вместе с врачом.
- Отсутствующее правило показывается предупреждением валидации. Бот и Mini
  App при этом возвращают понятное сообщение вместо внутренней ошибки.

Сейчас отсутствуют правила:

- `Жирная + Чувствительная / раздражённая + Любой`;
- `Сухая + Акне / высыпания + Любой`.

Для каждого из них врач должен определить основную рекомендацию,
альтернативы и профессиональный вариант.

## Безопасность синхронизации

- Все изменения выполняются в одной транзакции.
- Товары и правила добавляются или обновляются.
- Альтернативы заменяются только внутри синхронизируемого правила.
- Правила, отсутствующие в новом JSON, деактивируются, но не удаляются:
  история пройденных тестов сохраняет связи.
- Товары, отсутствующие в новом JSON, автоматически не удаляются.
- `doctorComment` и `imageUrl` сохраняются, если в каталоге они не заполнены.

Перед крупным обновлением production-каталога рекомендуется сделать резервную
копию MySQL.
